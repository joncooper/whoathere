# Artifact-Native Linux VZ Fanotify Queue-Overflow Checkpoint

Date: 2026-07-12

Status: `fanotify_queue_overflow` plus the twenty earlier physical cases pass on one exact measured
backend identity; the backend remains `candidate_unqualified` with 17 of 38 cases pending

## Outcome

The second drop-accounting gate now produces a real kernel fanotify queue overflow with bounded
global-state exposure and exact trigger attribution. The root-owned sensor creates 256 mode-0400
files in a mode-0700 directory and verifies that every file is a distinct, root-owned, single-link
inode. No other guest process can reach that directory.

The fault injector reads the system fanotify queue default, temporarily changes it from 16,384 to
64, creates one nonblocking notification group, and immediately restores and rereads the original
global value before installing a directory-only `FAN_OPEN | FAN_EVENT_ON_CHILD` mark. It then opens
each unique file exactly once without draining the group. The pinned kernel returned 64 exact-PID
normal open events plus one `FAN_Q_OVERFLOW` event. Because all 256 unique triggers succeeded and
cannot coalesce by inode, the bounded gap is exactly `256 - 64 = 192` events.

Strict Swift and Rust decoders require the original and injected limits, restored-limit proof, 256
unique inodes, 256 triggers, 64 observed events, one kernel overflow marker, 192 dropped events,
healthy sensor state, complete cleanup, and `incomplete_on_injected_gap`. Missing or duplicate
records, a zero overflow marker, an unrestored limit, inode reuse, noncanonical JSON, and any count
rebinding fail closed. The host independently reports a healthy packet sensor, zero dropped or raw
frames, terminated guest channel, stopped VM, and destroyed diskless execution instance with the
same terminal.
