## Outcome

The Swift helper core now has an sdist-specific `WHOASDI1` submission parser. It reads and
validates the fixed prefix and canonical header first, then returns a typed prelude while leaving
the artifact body unread. The prelude binds:

- canonical run-spec and scenario-template digests;
- exact build-closure digest;
- challenge and derived execution-binding digests;
- exact artifact digest and byte length;
- scenario identity and kind; and
- the complete measured macOS backend identity.

The parser rejects npm and wheel frame domains. It accepts only the closed sdist header, run-spec,
template, runtime-profile, offline build-closure, scenario, limits, evidence, and backend schemas.
Unknown keys, noncanonical JSON, invalid limits or trigger targets, closure substitution, runtime or
backend mismatch, artifact mutation, truncation, and trailing data fail closed.

Legacy `setup.py` scenarios use a canonical JSON `null` build backend. The shared canonical JSON
implementation now supports that value so the Swift contract matches the Rust sdist wire rather
than narrowing the typed scenario set.

## Exact-byte ordering

`beginSdistSubmission` consumes only the 56-byte prefix and bounded canonical header. It does not
read or forward the sdist body. The returned `SdistRunSubmissionReader` can stream the declared
artifact bytes once, verifies their SHA-256 while streaming, and requires immediate EOF.

This split creates the required lifecycle seam:

1. validate the sdist header and all nested bindings;
2. atomically burn the matching launch authority;
3. only after successful authority consumption, read or forward the artifact body.

No helper routing or guest channel uses the seam yet. That is the next integration gate.

## Swift single-use authority

The Swift authority consumer mirrors the committed Rust authority contract under the distinct
`sdist-authorities` state root. It requires an identifier of the exact form
`sdist-authority-<64 lowercase hex>`, plus the expected canonical authority-record digest.

Consumption atomically moves the record from `pending` to `consumed` with `renameatx_np` and
`RENAME_EXCL` before record digest, canonical JSON, expiry, or binding validation. It then:

1. syncs the pending, consumed, and authority-root directories;
2. opens the consumed record with `O_NOFOLLOW` and `O_CLOEXEC`;
3. requires a helper-owned, single-link, regular `0600` file under the 64 KiB ceiling;
4. verifies the caller-bound authority-record SHA-256;
5. validates the closed canonical authority record and 15-minute maximum lifetime;
6. uses the half-open validity interval `issued_at <= now < expires_at`; and
7. requires exact challenge, run-spec, artifact, and build-closure agreement with the validated
   submission prelude.

Successful, expired, tampered, and rebound records remain consumed. There is no restore path from
consumed to pending.

## Verification

The focused inert sdist suite has 8 passing tests. It proves:

- all five typed wire variants parse, including PEP 517 and legacy build forms;
- header validation leaves the artifact body unread and single-pass streaming preserves exact
  bytes;
- npm, wheel, and sdist frame domains are mutually rejected;
- truncated, trailing, mutated, unknown-key, cross-schema, and closure-rebound frames fail closed;
- authority consumption binds the exact run spec, artifact, challenge, and build closure before
  artifact reads;
- replay, exact-expiry, record-digest tamper, and closure rebinding are rejected and remain burned;
  and
- 12 concurrent consumers produce exactly one winner and eleven replay failures.

The complete packaged-helper suite passes 61 tests, and the helper builds successfully in release
mode. `git diff --check` is clean.

All fixtures contain inert generated bytes. No VM, guest process, package manager, build backend,
network, restricted sample, or malware was used.

## Claim boundary and next gate

This checkpoint proves a Swift helper-core parser and authority primitive. It does not prove that
the helper executable exposes an sdist command, that its production lifecycle consumes authority
before opening VZ or guest channels, that build-closure artifacts have a bounded transport, or that
any sdist behavior executes in a VM.

The next slice is to add an sdist-only helper invocation and lifecycle that accepts both authority
identifier and authority-record digest, calls `beginSdistSubmission`, consumes authority, and only
then permits guest authentication or artifact streaming. The lifecycle must remain non-executing,
zero-network, no-sync, and cleanup-complete in inert tests. A separately bounded exact build-closure
artifact channel follows that lifecycle gate.
