## Outcome

The final drop-accounting gate now produces a real, bounded overflow in the host packet-evidence
queue without stalling the guest or claiming socket backpressure as loss. A first physical attempt
that reduced the host kernel receive buffer caused virtio TX backpressure and was rejected
fail-closed. The final design continuously drains the private Virtualization.framework attachment
and attempts to reserve each frame in a fixed 64-frame evidence queue.

The unprivileged guest sends 512 checksum-valid UDP frames to the no-route documentation sinkhole.
Each 16-byte payload binds a fixed magic value, a distinct sequence from 0 through 511, its bitwise
complement, and the fixed trigger count. Guest evidence binds the ephemeral source port, 512
successful sends, an exact 512-packet `eth0` TX-counter delta, and zero TX drops or errors. The host
received all 512 frames, retained and strictly decoded the first 64 unique sequences, and counted
448 failed evidence-queue admissions. The exact relation is `64 + 448 = 512`.

Strict Swift and Rust decoders require the 64-frame queue capacity, 512 guest triggers and host
ingress frames, 64 retained raw frames, 64 unique valid sequences, zero duplicates, zero unexpected
retained frames, 448 drops, healthy sensors, complete teardown, and
`incomplete_on_injected_gap`. The private attachment has no route or forwarding path. Missing,
duplicate, noncanonical, rebound, or arithmetically inconsistent evidence fails closed.
